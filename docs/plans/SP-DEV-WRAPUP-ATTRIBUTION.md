# SP-DEV-WRAPUP-ATTRIBUTION — Wrap-up attributes cross-cutting breakage to its introducing step and repairs it

Add a pure `attribute_failure_to_step` helper in a new `src/ferova/review/wrapup_attribution.py` that walks a plan's ordered step commits (base first) against an injectable selector runner to name which commit introduced a wrap-up test failure, or reports it `pre_existing` when already red at the plan base, or `error` when the runner itself raises. Wire it into `dev_runner`'s wrap-up path: when the full unit suite is red on selectors no step promised, build a real git-worktree selector runner and a step-commit map, attribute each failing selector, dispatch exactly `WRAPUP_REPAIR_ATTEMPTS` (1) bounded repair per introducing step to the existing Developer loop with a brief carrying the selector, step title, files and diff, commit `fix(wrapup): <selector> broken by step <n>` on success, and on failure populate `no_op_reason` and a new `wrapup_dossier` field naming the step index/title/selector instead of the bare 'full unit suite pytest red'.

## Step 1 — Add the pure step-attribution helper

- **Files**: `src/ferova/review/wrapup_attribution.py`, `tests/unit/test_wrapup_attribution.py`
- **Action**: Create `src/ferova/review/wrapup_attribution.py` with a module docstring explaining its role in the wrap-up path (dev_runner.py wires it in a later step). Define `@dataclass(frozen=True) class StepCommit` with fields `index: int`, `title: str`, `sha: str` (index `0` conventionally names the plan base, not a real step). Define `@dataclass(frozen=True) class AttributionOutcome` with fields `selector: str`, `status: Literal["introduced_by_step", "pre_existing", "error"]`, `step: StepCommit | None = None`, `error: str | None = None`. Define `def attribute_failure_to_step(selector: str, step_commits: list[StepCommit], *, run_selector: Callable[[str, str], bool]) -> AttributionOutcome` with a Google-style docstring: `step_commits[0]` is always the plan base; the function first calls `run_selector(step_commits[0].sha, selector)` inside a try/except `Exception` (any raise returns `AttributionOutcome(selector, status="error", error=str(exc)[:300])` immediately — fail-closed); if that call returns falsy, return `AttributionOutcome(selector, status="pre_existing", step=step_commits[0])`; otherwise walk `step_commits[1:]` in order, calling `run_selector(commit.sha, selector)` the same fail-closed way, and return `AttributionOutcome(selector, status="introduced_by_step", step=commit)` for the first one that returns falsy; if every commit is green (or `step_commits` has only the base entry), return `AttributionOutcome(selector, status="error", error="selector green at every recorded commit; attribution inconclusive")`. The function performs no I/O itself — it only calls the injected `run_selector`. In `tests/unit/test_wrapup_attribution.py`, add local helpers `_git(repo, *args)` (subprocess `git` in `repo`, returns combined stdout+stderr) and `_init_repo(tmp_path)` (creates `repo/src` + `repo/tests/unit`, `git init -q`, sets `user.email`/`user.name`, writes and commits an initial passing `tests/unit/test_demo.py::test_ok`), plus a `_real_run_selector(repo)` factory returning a closure `(sha, selector) -> bool` that runs `git worktree add --detach <tmp worktree dir> <sha>` in `repo`, runs `python -m pytest -q <selector>` with `cwd` set to that worktree dir, removes the worktree with `git worktree remove --force`, and returns `returncode == 0` (propagate any `git worktree add` failure as a raised `RuntimeError`). Then write three tests: (a) `test_attribution_names_introducing_step` — commit a step-1 change that keeps `test_ok` green, commit a step-2 change that rewrites `test_demo.py` to fail, build `step_commits = [StepCommit(0, "plan base", base_sha), StepCommit(1, "step one", step1_sha), StepCommit(2, "step two", step2_sha)]`, call `attribute_failure_to_step("tests/unit/test_demo.py::test_ok", step_commits, run_selector=_real_run_selector(repo))`, assert `result.status == "introduced_by_step"` and `result.step.index == 2`; (b) `test_attribution_reports_pre_existing_failure` — make the BASE commit's `test_ok` already fail, add two step commits that never fix it, assert `result.status == "pre_existing"` and `result.step.index == 0`; (c) `test_attribution_runner_error_fails_closed` — pass a `run_selector` that raises `RuntimeError("worktree exploded")` unconditionally, assert `result.status == "error"` and `"worktree exploded" in result.error`, and that no exception escapes the call.
- **Commit**: `feat(wrapup-attribution): add pure step-attribution helper for wrap-up failures`
- **Done when**: python -m pytest tests/unit/test_wrapup_attribution.py -q passes
- **Unit tests**: `tests/unit/test_wrapup_attribution.py::test_attribution_names_introducing_step`, `tests/unit/test_wrapup_attribution.py::test_attribution_reports_pre_existing_failure`, `tests/unit/test_wrapup_attribution.py::test_attribution_runner_error_fails_closed`

## Step 2 — Add worktree selector runner and step-commit mapping to dev_runner

- **Files**: `src/ferova/review/dev_runner.py`, `tests/unit/test_dev_runner_wrapup.py`
- **Action**: In `src/ferova/review/dev_runner.py`, add `import tempfile` next to the existing `import shutil` / `import subprocess` block, and add module-level constant `WRAPUP_REPAIR_ATTEMPTS: int = 1` next to `_MAX_STEP_ATTEMPTS` (around line 194) with a one-line docstring-style comment via a module docstring constant (following the `_MAX_STEP_ATTEMPTS` pattern — a `"""..."""` string literal right after the assignment) explaining it bounds the wrap-up repair loop per introducing step (SP-DEV-WRAPUP-ATTRIBUTION). Immediately after `_changed_paths` (around line 991), add four functions with Google-style docstrings: (1) `_run_selector_at_commit(repo_root: Path, sha: str, selector: str) -> bool` — creates `tempfile.mkdtemp(prefix="ferova-wrapup-")`, runs `_run_git(repo_root, "worktree", "add", "--detach", tmp_dir, sha)`, raises `RuntimeError(out)` when that call's return code is nonzero, otherwise calls `run_pytest_selectors(Path(tmp_dir), [selector])` and captures the green boolean, and in a `finally` block always runs `_run_git(repo_root, "worktree", "remove", "--force", tmp_dir)` followed by `shutil.rmtree(tmp_dir, ignore_errors=True)`, then returns the captured boolean; (2) `_step_commits_for_plan(repo_root: Path, plan: ActionPlan, base: str) -> list[StepCommit]` (import `StepCommit` from `.wrapup_attribution`) — resolves `rc, merge_base = _run_git(repo_root, "merge-base", "HEAD", base, tail_chars=0)`, returns `[]` when `rc != 0`; otherwise builds `commits = [StepCommit(index=0, title="plan base", sha=merge_base.strip())]`, runs `_run_git(repo_root, "log", "--format=%H%x1f%s", "--reverse", f"{merge_base.strip()}..HEAD", tail_chars=0)`, parses each output line by splitting on `\x1f` into `(sha, subject)`, and for every `step in plan.steps` whose `step.commit_message == subject` for some parsed line, appends `StepCommit(index=step.index, title=step.title, sha=sha)` in plan order; returns `commits`; (3) `_promised_selectors_for_plan(plan: ActionPlan) -> set[str]` — returns `set(plan.integration_tests) | {t for step in plan.steps for t in step.unit_tests}`; (4) `_collect_failing_wrapup_selectors(repo_root: Path, promised: set[str]) -> list[str]` — runs (local `import sys`) `subprocess.run([sys.executable, "-m", "pytest", "-q", "--tb=no", "-rf", "tests/unit"], cwd=repo_root, capture_output=True, text=True, timeout=900, check=False, env=scrubbed_env())`, parses every stdout line starting with `"FAILED "` by taking its second whitespace-separated token as the selector, and returns the sorted set of those selectors that are NOT in `promised`. In `tests/unit/test_dev_runner_wrapup.py`, add local helpers `_git(repo, *args)` and `_init_repo(tmp_path)` mirroring `tests/unit/test_review_plan_executor.py`'s (`repo/src`, `repo/tests/unit`, `git init -q`, commit an initial passing test on a `develop` branch, then `git switch -c impl` off it) plus a small `_one_step_plan()`-style `ActionPlan` builder reusing `ferova.review.plan.ActionPlan`/`PlanStep`. Write two tests: (a) `test_step_commits_for_plan_maps_base_and_steps_in_order` — on the `impl` branch, make two commits whose subjects equal two `PlanStep.commit_message` values in a 2-step `ActionPlan`, call `_step_commits_for_plan(repo, plan, "develop")`, assert the result has 3 entries with `index == [0, 1, 2]` and `sha` values matching `git rev-parse` of the merge-base and each commit; (b) `test_collect_failing_wrapup_selectors_excludes_promised` — write `tests/unit/test_wrap_demo.py` with one failing `test_a` and one failing `test_b`, call `_collect_failing_wrapup_selectors(repo, {"tests/unit/test_wrap_demo.py::test_a"})`, assert the returned list contains `tests/unit/test_wrap_demo.py::test_b` and not `test_a`.
- **Commit**: `feat(dev_runner): add worktree selector runner and step-commit mapping for wrap-up attribution`
- **Done when**: python -m pytest tests/unit/test_dev_runner_wrapup.py -q passes
- **Unit tests**: `tests/unit/test_dev_runner_wrapup.py::test_step_commits_for_plan_maps_base_and_steps_in_order`, `tests/unit/test_dev_runner_wrapup.py::test_collect_failing_wrapup_selectors_excludes_promised`

## Step 3 — repair_wrapup_failures: bounded attributed repair (split 2026-07-09: the _develop_one_spec wiring moved to step 4 after a turn-budget blowout; narrative below describes both halves, the JSON block is authoritative)

- **Files**: `src/ferova/review/dev_runner.py`, `tests/unit/test_dev_runner_wrapup.py`
- **Action**: In `src/ferova/review/dev_runner.py`, add `wrapup_dossier: str = ""` as a new field on `DevSessionResult` (near `no_op_reason`, around line 234) with a one-line addition to the class docstring noting it carries the SP-DEV-WRAPUP-ATTRIBUTION attribution block. Import `attribute_failure_to_step` from `.wrapup_attribution` at the top of the file next to the other `.` imports. Add a new function `repair_wrapup_failures(repo_root: Path, plan: ActionPlan, *, dev: Developer, db: Path, base: str, failing_selectors: list[str], result: DevSessionResult) -> str | None` placed after `_collect_failing_wrapup_selectors`, with a Google-style docstring describing: it builds `step_commits = _step_commits_for_plan(repo_root, plan, base)`; for each selector in `failing_selectors` it calls `attribute_failure_to_step(selector, step_commits, run_selector=lambda sha, sel: _run_selector_at_commit(repo_root, sha, sel))` inside a try/except `Exception` that on any escape appends `f"error: {selector}: attribution crashed: {exc}"` to a local `dossier_lines` list and records the selector as unrepaired; for a `pre_existing` outcome it appends `f"pre_existing: {selector}"` to `dossier_lines` and does not attempt repair (NG3); for an `error` outcome it appends `f"error: {selector}: {outcome.error}"` and records it unrepaired; for an `introduced_by_step` outcome it looks up the matching `PlanStep` via `next(s for s in plan.steps if s.index == outcome.step.index)`, computes a diff via `_run_git(repo_root, "show", "--stat", outcome.step.sha, tail_chars=0)`, builds a repair brief string naming the selector, the step's `index`/`title`, its `files`, and the diff stat, then loops `range(WRAPUP_REPAIR_ATTEMPTS)` calling `dev.develop_step(brief=brief, repo_root=repo_root, allowed_paths=list(matched_step.files) + [selector.split("::", 1)[0]], repo_tree="", spec_id=f"{plan.spec_id}:wrapup-repair-step-{outcome.step.index}")`, then `record_coder_response(db, pr_number=0, plan={"fixes": [], "commit_message": f"fix(wrapup): {selector} broken by step {outcome.step.index}", "summary": f"wrapup repair attempt for {selector}"}, model_used=loop_result.model_used, elapsed_s=loop_result.elapsed_s, tokens_used=loop_result.tokens_used)`, then checks `ok, _ = run_pytest_selectors(repo_root, [selector])` (the function returns a tuple — unpack it, never truth-test it); on green (`ok`) it calls `commit_all(repo_root, f"fix(wrapup): {selector} broken by step {outcome.step.index}")` and breaks out of the attempt loop as repaired; when the attempts are exhausted without green it appends `f"step {outcome.step.index} ({matched_step.title}): {selector}"` to `dossier_lines` and records it unrepaired. After processing every selector, set `result.wrapup_dossier = "\n".join(dossier_lines)`; if any selector stayed unrepaired, return a `no_op_reason` string built from the FIRST unrepaired entry: for an `introduced_by_step` case return `f"full unit suite pytest red \u2014 step {step_index} ({step_title}) introduced a failure in {selector} and the bounded repair attempt did not fix it"`; for a `pre_existing` or `error` case return `f"full unit suite pytest red \u2014 {dossier_line}"`; otherwise (every selector repaired) return `None`. Wire it into `_develop_one_spec`'s wrap-up block (around line 1509-1513): replace the bare `if not full_ok: return f"full unit suite pytest red after all steps ({full_tail[:160]})"` with: compute `promised = _promised_selectors_for_plan(action_plan)`, `failing = _collect_failing_wrapup_selectors(repo, promised)` when `not full_ok`; when `failing` is non-empty call `reason = repair_wrapup_failures(repo, action_plan, dev=dev, db=db, base=base, failing_selectors=failing, result=result)`, return `reason` immediately when it is not `None`, otherwise re-run `full_ok, full_tail = run_pytest_matrix(repo)` and update `result.pytest_passed = full_ok`; finally keep the original `if not full_ok: return f"full unit suite pytest red after all steps ({full_tail[:160]})"` as the closing fallback (covers the `failing` empty case and a repair that still leaves the full suite red for unrelated reasons). In `tests/unit/test_dev_runner_wrapup.py`, reuse this step's repo/plan helpers to add two tests calling `repair_wrapup_failures` directly against a real tmp git repo with a base commit and one step commit that breaks an unpromised test `tests/unit/test_wrap_demo.py::test_b`: (a) `test_wrapup_red_dispatches_attributed_repair` — a fake `Developer` (a `MagicMock` whose `develop_step` records its call kwargs, writes a fixed passing version of `tests/unit/test_wrap_demo.py` to `repo_root`, and returns a `DevLoopResult`) is passed as `dev`; call `repair_wrapup_failures(...)`; assert `dev.develop_step` was called exactly once (respecting `WRAPUP_REPAIR_ATTEMPTS == 1`) and that its `allowed_paths` kwarg contains the selector's file path and that its `allowed_paths` kwarg contains the selector's file path and that its `brief` kwarg contains the selector string, the step's title, at least one of the step's `files`, and a diff-stat-shaped line (e.g. contains `"file changed"` or `"|"`); assert the function returns `None` and a new commit whose subject starts with `"fix(wrapup): tests/unit/test_wrap_demo.py::test_b broken by step"` exists in `git log`; (b) `test_wrapup_no_op_reason_names_step` — the fake `Developer` leaves the test red (writes nothing, or rewrites it still failing); call `repair_wrapup_failures(...)`; assert the returned string contains the step's `index` (as a string) and `title`, and the selector `tests/unit/test_wrap_demo.py::test_b`; assert `result.wrapup_dossier` also contains the step's title and the selector.
