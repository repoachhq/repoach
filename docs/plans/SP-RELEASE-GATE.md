# SP-RELEASE-GATE — Evidence-first gate for the develop → main release

Add a new leaf module src/ferova/review/release_gate.py mirroring the existing pure merge-gate pattern (merge_gate.py / auto_merge.py): a pure commit-subject classifier for release-range provenance, a fact-gatherer that shells out to git/gh/scripts/ci_local.sh, a pure decision function that refuses on any red fact, and a receipt round-trip for a post-merge verify step. Wire it up as `ferova release gate [--pr N]` / `ferova release verify` in a new src/ferova/cli/release_cmds.py mounted on the main Typer app, exit-coding 0/5/1 exactly like `ferova review gate`. The gate only prints facts and a decision — it never shells out to `gh pr merge` — so the operator keeps sole authority over the actual merge.

## Step 1 — Pure release-range classifier + decision core

- **Files**: `src/ferova/review/release_gate.py`, `tests/unit/test_release_gate.py`
- **Action**: Create src/ferova/review/release_gate.py (module docstring citing SP-RELEASE-GATE, `from __future__ import annotations`, Google-style docstrings, no inline comments). Add: `import re` and `_SQUASH_SUBJECT_RE = re.compile(r"\(#\d+\)$")`. `classify_release_range(subjects: list[str]) -> list[str]` — pure: returns the subset of `subjects` whose stripped text does NOT match `_SQUASH_SUBJECT_RE.search(subject.strip())`; an empty input or all-matching input returns `[]`. Add pydantic `BaseModel` classes (mirror `merge_gate.MergeFacts`/`MergeDecision` shape and docstring style): `ReleaseFacts` with fields `develop_sha: str`, `out_of_band_commits: list[str] = []`, `remote_sha: str`, `pr_head_sha: str | None = None`, `ci_green: bool`, `ci_checked: bool = True` (False only when CI could not be evaluated at all — reserved for step 2); and `ReleaseDecision` with `merge: bool`, `reasons: list[str]`. Add `compute_release_decision(facts: ReleaseFacts) -> ReleaseDecision` — pure, appends one reason per red fact (out-of-band commits named by subject, `develop_sha != remote_sha` head-freshness mismatch, `pr_head_sha is not None and pr_head_sha != develop_sha` PR staleness, `not ci_green` CI red) and returns `ReleaseDecision(merge=not reasons, reasons=reasons)`. In tests/unit/test_release_gate.py add a module docstring, then `test_release_range_all_squashes` (list of subjects each ending `(#12)` etc → `classify_release_range` returns `[]`), `test_release_range_flags_non_pr_commit` (one subject without the suffix mixed into an otherwise-clean list → returned list contains exactly that subject), and `test_release_gate_fail_closed_on_red_ci` (construct a green `ReleaseFacts` via a local `_facts(**over)` helper mirroring `test_merge_gate.py`'s pattern, override `ci_green=False`, assert `compute_release_decision(...).merge is False` and a reason mentions CI).
- **Commit**: `feat(release): pure release-range classifier and decision core`
- **Done when**: python -m pytest tests/unit/test_release_gate.py::test_release_range_all_squashes tests/unit/test_release_gate.py::test_release_range_flags_non_pr_commit tests/unit/test_release_gate.py::test_release_gate_fail_closed_on_red_ci -q passes and ruff check src/ferova/review/release_gate.py exits 0
- **Unit tests**: `tests/unit/test_release_gate.py::test_release_range_all_squashes`, `tests/unit/test_release_gate.py::test_release_range_flags_non_pr_commit`, `tests/unit/test_release_gate.py::test_release_gate_fail_closed_on_red_ci`

## Step 2 — gather_release_facts: provenance, head freshness, CI mirror

- **Files**: `src/ferova/review/release_gate.py`, `tests/unit/test_release_gate.py`
- **Action**: In release_gate.py add `import subprocess`, `from collections.abc import Callable`, `from pathlib import Path`, and `from .gh_client import GhCli`. Add module constant `_DEFAULT_CI_SCRIPT = "scripts/ci_local.sh"`. Add `def _default_ci_runner(repo_root: Path) -> subprocess.CompletedProcess: script = repo_root / _DEFAULT_CI_SCRIPT; if not script.is_file() or not os.access(script, os.X_OK): raise FileNotFoundError(f"{script} missing or not executable"); return subprocess.run([str(script)], cwd=repo_root, capture_output=True, text=True, check=False)` (add `import os`). Add `gather_release_facts(*, repo_root: Path, gh: GhCli, pr_number: int | None = None, ci_runner: Callable[[Path], subprocess.CompletedProcess] | None = None) -> ReleaseFacts`: runs `gh._run_git(["rev-parse", "develop"])` for `develop_sha`; `gh._run_git(["log", "main..develop", "--format=%s"])` split on newlines (drop blanks) into `subjects`, then `out_of_band_commits = classify_release_range(subjects)`; `gh._run_git(["ls-remote", "origin", "develop"])` and take the first whitespace-split token of the first stdout line as `remote_sha` (empty string when the command fails or output is blank); `pr_head_sha = gh.pr_head_sha(pr_number) if pr_number is not None else None`; runs `(ci_runner or _default_ci_runner)(repo_root)` — this call is NOT wrapped in try/except, so a `FileNotFoundError` from `_default_ci_runner` (or any exception from an injected fake) propagates straight out of `gather_release_facts` (fail-closed: the caller must treat this as an evaluation error, never a fact); `ci_green = (result.returncode == 0)`. Returns the assembled `ReleaseFacts`. Add to test_release_gate.py: a `_gh_stub(*, develop_sha, remote_sha, pr_head_sha=None)` helper returning a `MagicMock` (mirror `tests/unit/test_review_gate.py`'s `_gh` helper) whose `_run_git` and `pr_head_sha` are wired via `side_effect`/`return_value`. `test_release_gate_refuses_stale_head` — stub with `develop_sha != remote_sha`, a fake `ci_runner` returning `subprocess.CompletedProcess([], 0)`, call `gather_release_facts` then `compute_release_decision`, assert `merge is False` and a reason names the mismatch. `test_release_gate_missing_ci_script_is_error` — call `gather_release_facts(repo_root=tmp_path, gh=_gh_stub(develop_sha='a', remote_sha='a'))` with NO `ci_runner` override against an empty `tmp_path` (no `scripts/ci_local.sh`), wrapped in `pytest.raises(FileNotFoundError)`.
- **Commit**: `feat(release): gather release-range, head-freshness and CI-mirror facts`
- **Done when**: python -m pytest tests/unit/test_release_gate.py::test_release_gate_refuses_stale_head tests/unit/test_release_gate.py::test_release_gate_missing_ci_script_is_error -q passes and ruff check src/ferova/review/release_gate.py exits 0
- **Unit tests**: `tests/unit/test_release_gate.py::test_release_gate_refuses_stale_head`, `tests/unit/test_release_gate.py::test_release_gate_missing_ci_script_is_error`

## Step 3 — Gate receipt round-trip + post-merge verify

- **Files**: `src/ferova/review/release_gate.py`, `tests/unit/test_release_gate.py`
- **Action**: In release_gate.py add `import json` and a `ReleaseVerifyResult` `BaseModel` with fields `verified: bool`, `main_sha: str`, `expected_sha: str`, `detail: str`. Add `write_gate_receipt(path: Path, *, develop_sha: str, decision: ReleaseDecision) -> None` — `path.parent.mkdir(parents=True, exist_ok=True)`; writes `json.dumps({'develop_sha': develop_sha, 'merge': decision.merge, 'reasons': decision.reasons}, indent=2)` to `path`. Add `verify_release(path: Path, *, gh: GhCli) -> ReleaseVerifyResult` — reads and `json.loads`s the receipt at `path` (let `FileNotFoundError`/`json.JSONDecodeError` propagate — evaluation error, mirrors the CI-script fail-closed contract from step 2); `expected_sha = data['develop_sha']`; resolves the live `main` tip via the first whitespace-split token of `gh._run_git(['ls-remote', 'origin', 'main']).stdout`'s first line; `verified = bool(expected_sha) and main_sha == expected_sha`; `detail` is `'main tip matches the approved develop head'` when verified else `'main tip does not match the approved develop head — squash or stale merge? revert and re-merge as a merge commit'`. Returns the assembled `ReleaseVerifyResult`. Also add a module-level docstring note (no runtime assertion — this is a code-shape guarantee, not a test fixture) stating the module never calls `gh pr merge` or `git push`. In test_release_gate.py add `test_release_verify_detects_squash_divergence` — write a receipt via `write_gate_receipt` with `develop_sha='deadbeef'`, stub `gh._run_git` to return a `ls-remote` line for a DIFFERENT sha, call `verify_release`, assert `verified is False` and `detail` mentions squash/stale. Add `test_release_gate_never_calls_merge` — `assert 'pr merge' not in Path('src/ferova/review/release_gate.py').read_text(encoding='utf-8')` (also assert `'gh pr merge'` and `'git push'` are absent) using the actual module source path relative to the repo root (resolve via `Path(__file__).resolve().parents[2] / 'src' / 'ferova' / 'review' / 'release_gate.py'`).
- **Commit**: `feat(release): gate receipt round-trip and post-merge verify`
- **Done when**: python -m pytest tests/unit/test_release_gate.py::test_release_verify_detects_squash_divergence tests/unit/test_release_gate.py::test_release_gate_never_calls_merge -q passes and ruff check src/ferova/review/release_gate.py exits 0
- **Unit tests**: `tests/unit/test_release_gate.py::test_release_verify_detects_squash_divergence`, `tests/unit/test_release_gate.py::test_release_gate_never_calls_merge`

## Step 4 — CLI wiring: ferova release gate / verify

- **Files**: `src/ferova/cli/release_cmds.py`, `src/ferova/cli/main.py`, `tests/unit/test_release_cli.py`
- **Action**: Create src/ferova/cli/release_cmds.py (module docstring, `from __future__ import annotations`) mirroring the `review_gate` command in `src/ferova/cli/review_cmds.py`: `release_app = typer.Typer(help='Operator-only develop -> main release gate (read-only, never merges).', no_args_is_help=True)`. `_RECEIPT_PATH = Path('tmp/release_gate_receipt.json')`. `_repo_root() -> Path: return Path(__file__).resolve().parents[3]` (mirrors `arch_check`'s repo-root resolution in main.py). `@release_app.command('gate')` `def release_gate(pr_number: int | None = typer.Option(None, '--pr', help='Release PR number (adds PR head-freshness check).')) -> None`: builds `gh = GhCli(cwd=_repo_root())`, wraps `gather_release_facts(repo_root=_repo_root(), gh=gh, pr_number=pr_number)` in try/except `Exception`, on failure echoes a JSON `{'error': str(exc)}` and `raise typer.Exit(code=1)`; on success computes `decision = compute_release_decision(facts)`, calls `write_gate_receipt(_RECEIPT_PATH, develop_sha=facts.develop_sha, decision=decision)`, echoes JSON with `develop_sha`, `out_of_band_commits`, `remote_sha`, `pr_head_sha`, `ci_green`, `merge`, `reasons`, and (only when `decision.merge` is True) a `required_merge_method` field fixed to `'Create a merge commit — never squash a release.'`; `raise typer.Exit(code=5)` when `not decision.merge`. `@release_app.command('verify')` `def release_verify() -> None`: `gh = GhCli(cwd=_repo_root())`, wraps `verify_release(_RECEIPT_PATH, gh=gh)` in try/except `Exception` → JSON error + exit 1; echoes JSON `{'verified', 'main_sha', 'expected_sha', 'detail'}`; `raise typer.Exit(code=5)` when not verified. In main.py add `from .release_cmds import release_app` and `app.add_typer(release_app, name='release')` next to the existing `app.add_typer(review_app, name='review')` line. Create tests/unit/test_release_cli.py (mirror `tests/unit/test_review_gate.py`'s CLI section): `test_cli_release_gate_exit_zero_when_merge_ready` (monkeypatch `release_cmds.gather_release_facts` to return an all-green `ReleaseFacts`, call `release_cmds.release_gate(None)` directly, assert no exception), `test_cli_release_gate_exit_five_when_refused` (monkeypatch to return a `ReleaseFacts` with `ci_green=False`, assert `pytest.raises(typer.Exit)` with `exit_code == 5`), `test_cli_release_verify_exit_five_on_divergence` (monkeypatch `release_cmds.verify_release` to return a `ReleaseVerifyResult(verified=False, ...)`, assert `typer.Exit` with `exit_code == 5`).
- **Commit**: `feat(release): wire ferova release gate/verify CLI commands`
- **Done when**: python -m pytest tests/unit/test_release_cli.py -q passes and python -c "from ferova.cli.main import app" succeeds and ruff check src/ferova/cli/release_cmds.py src/ferova/cli/main.py exits 0
- **Unit tests**: `tests/unit/test_release_cli.py::test_cli_release_gate_exit_zero_when_merge_ready`, `tests/unit/test_release_cli.py::test_cli_release_gate_exit_five_when_refused`, `tests/unit/test_release_cli.py::test_cli_release_verify_exit_five_on_divergence`

In `test_release_gate_clean_range_then_out_of_band_refusal(tmp_path)`: build a bare `origin` repo at `tmp_path / 'origin.git'` (`git init --bare`), clone it to `tmp_path / 'work'`, configure `user.email`/`user.name`, create `main` with one commit, branch `develop` off it, add 2 commits each with a subject ending `(#N)` (squash-shaped), push both branches to `origin`. Build a `GhCli(cwd=work_dir)` (no `gh` calls needed — only `_run_git` paths are exercised) and a fake `ci_runner` lambda returning `subprocess.CompletedProcess([], 0)`. Call `gather_release_facts(repo_root=work_dir, gh=gh, ci_runner=fake_ci_runner)` then `compute_release_decision(facts)`, assert `merge is True` and `reasons == []`. Then add one more commit on `develop` with a subject NOT ending `(#N)` (the out-of-band commit) and push it, re-run `gather_release_facts` + `compute_release_decision`, assert `merge is False` and the out-of-band commit's subject appears in `reasons`.
